## Platform

web

## Users

React developers exploring, customizing and installing reusable interface components. This is confirmed by the existing documentation and the owner's request to improve the component playground and editor.

## Product Purpose

oRangeUi is a React and TypeScript component library with working demonstrations, editable artwork, visual effects, accessible controls and downloadable source. Visitors can try components, change their settings and bring the source into a project.

## Capabilities and Constraints

- The existing Next.js 16 app uses React 19, TypeScript and Tailwind, with local component styles.
- Polished, Pixelated, Neobrutalism, Retro OS and Terminal are separate appearances. Light and dark palettes are independent.
- Installation is available through a shadcn-compatible registry and complete source ZIPs.
- The repository's license is MIT. No paid tiers, customer metrics or endorsements have been supplied.
- Real previews, keyboard access, responsive layouts, reduced-motion behavior and static renderer fallbacks are established requirements.

## Brand Commitments

Keep the oRangeUi name and existing orange pixel logo. The owner approved the supplied landscape reference for the new landing page, a floating glass playground dock, and a clearer editor with its own visual identity. Preserve the previous landing as a working fallback.

## Evidence on Hand

The component registry, implemented examples, source download pipeline and existing project documentation are product evidence. The six-task request and landing-scene brief were recovered from the preceding conversation and explicitly approved for continuation on 1 November 2026. Reference assets are provided by the owner; unrelated reference interface text must not appear in the finished page.

## Product Principles

- Show working behavior and immediately usable source.
- Make editing controls clearly interactive and keep the preview visible.
- Keep component navigation predictable.
- Keep the public catalogue focused on useful standalone APIs. Label experiments explicitly and keep supporting recipes inside their demos.
- Match the owner's supplied visual references and preserve useful existing routes.
